sloprail runs inside your agent as a **plugin**, and its hooks call a separate
set of binaries (`sr`, `sr-session`, `sr-file`, `sr-mark`, `sr-agent`). Both
steps below are required — the plugin without the binaries is a session that
runs unguarded with no warning, which is exactly the failure this page exists
to prevent.

## 1. Install the binaries

```bash
curl -fsSL https://raw.githubusercontent.com/sloprail/sloprail/main/install.sh | sh
```

This downloads the right prebuilt archive for your platform (macOS or Linux,
Intel or Apple Silicon/arm64) from the latest GitHub release, verifies its
checksum, and installs the five binaries into `~/.local/bin` — set
`SLOPRAIL_INSTALL_DIR` first to choose a different directory. No Go toolchain
needed.

Already have Go? `go install ./services/...` from a checkout of
[sloprail/sloprail](https://github.com/sloprail/sloprail) is an equivalent
fallback — it lands the same five binaries in one directory, which is all
`install.sh` does too, just without needing Go.

## 2. Install the plugin

<Tabs>
  <TabItem label="Claude Code">
    ```bash
    /plugin install sloprail@sloprail-marketplace
    ```

    That's it — the hooks are registered. A project with a `.sloprail/` directory
    is now guarded; a project with none is an ordinary project until its first
    rule.
  </TabItem>
</Tabs>

More harnesses will get their own tab as they go live. The engine's contract —
hook points in, events out — isn't specific to one, so the rules a project writes
don't change between them.

## Verify it worked

```bash
sr-session start < /dev/null
```

should print the load check with no errors. If you skipped step 1 or
`~/.local/bin` isn't on `$PATH`, the very next tool call in your agent will say
so loudly — sloprail never fails silently on a missing install; the guarded
action is blocked with the install command repeated until it can find
`sr-session`.
