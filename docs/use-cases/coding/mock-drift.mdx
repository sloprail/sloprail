## The failure

Code written to imitate a real system — a mock, a stub, an emulator — has no
standing check that it still matches that system's contract. The real thing
changes; the imitation does not. It drifts silently, and everything built and
tested against the mock keeps looking fine, because the mock is the only thing
those tests ever see. The gap surfaces the first time the code meets the real
system it was supposed to stand in for.

<UseCase id="mock-drift" label="Watch it happen — then get refused" />

## How it works

The mock carries a marker naming the real doc it conforms to. The marker's target
is a remote URL, so there is nothing to fetch ahead of time — the judge visits it
directly, the way a person checking this by hand would open the doc and read
across.

<Steps>

1. The guardrail fires on any code carrying a `conforms-to-doc` marker.

2. A judge opens the doc the marker names and rules on whether the marked code
   still follows the same contract.

</Steps>

This is a **file-guard** with a single judge check: the failure is one only a
model reading both sides can see, so there is no cheap script to gate it.
