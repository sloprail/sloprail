## The failure

An agent touches a file or takes an action without the prerequisite context — a
skill, a doc, a checklist — actually being loaded first. The action proceeds as
if the step happened, and afterward there's no way to tell that it didn't:
"available" reads the same as "loaded" once the work is done. The record that
was supposed to shape the action never entered the run, and nothing marks its
absence.

<UseCase id="acted-without-context" label="Watch it happen — then get refused" />

## How it works

The action is blocked until the required context is actually present in the run.
The requirement is answered against what really happened — was this skill loaded
this session — not against a claim that it was.

<Steps>

1. Writing under a governed path fires a **gate** in the pre-phase, before the
   write lands.

2. The gate's `require` names the skill that must have loaded first. If it
   hasn't, the write is denied until the prerequisite is met.

</Steps>

This is a **precondition**: a gate whose `require` is the whole rule — no check
script, because the requirement itself is the refusal.

### gate

Each gate binds a governed path to the skill it demands. A separate gate per
path, because `require` binds to the whole gate — which prefix demands which
skill is the structure itself. No checks: the `require` is the entire rule.
