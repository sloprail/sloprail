## The failure

Something you asked for never became a task, and never got explicitly dismissed
either. It didn't error and it wasn't refused — it just fell out of view between
one thing and the next. Nothing marks the gap, because a request that vanishes
leaves nothing behind to notice. The only signal is later, when the thing you
expected never arrives.

<UseCase id="request-fell-through" label="Watch it happen — then get refused" />

## How it works

Every request has to end up accounted for — either mapped to a task or explicitly
mapped to nothing. This is reconciliation: collect all the requests, subtract the
ones that were handled, and refuse if anything is left.

<Steps>

1. A **context** records each request the agent explicitly excuses — a declared
   dismissal that names exactly which message needs no task — into its own
   registry.

2. A **gate** at `Stop` collects every request, subtracts the ones a task
   references and the ones explicitly excused, and refuses if any residue is
   left unaccounted for.

</Steps>

A context can only track; the gate is what refuses the incomplete turn.
