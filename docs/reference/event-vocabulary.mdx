A guardrail binds to **events** in its `on:` list. An event is a flat fact about
what is happening — a tool about to run, a file about to be written, a turn about
to end. The kinds below are **generated from the engine's own event constants**,
so they match exactly what a rule can bind to.

## The set is per-build — confirm with the load check

The exact kinds available are whatever the modules compiled into *your* build
produce. The authoritative list for a given build is what the load check reports:

```bash
sr session start < /dev/null
```

Bind to a kind your build doesn't produce and it names every kind that *is*
available — so a typo is caught at load, not silently ignored.

## Aliases

An alias is a shorthand a trigger's `event` may name in place of a concrete kind;
the loader expands it on read, so one `match` covers several triggers.

## Matching

Binding to a kind is the coarse filter. Narrow further with `match:` over the
event's fields and surrounding state — `event.path startsWith "memories/"`, or
`context["refactoring"].active`. See
[Nature YAML shapes](/reference/nature-shapes) for the expression surface.
