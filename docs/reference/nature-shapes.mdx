Every guardrail is a folder under `.sloprail/`, named for the rule, containing a
`<nature>.yaml` declaration and the scripts it names. The fields below are
**generated from the engine's own declaration types** — the same struct tags and
doc comments the loader compiles against — so what you read here is exactly what
the code accepts. It is regenerated by `go generate ./...`; it is not hand-edited.

))}

## The natures on disk

- `FileGuard` → `.sloprail/file-guard/<name>/file-guard.yaml`
- `Gate` → `.sloprail/gate/<name>/gate.yaml`
- `Context` → `.sloprail/context/<name>/context.yaml`
- `StructureGate` → `.sloprail/structure-gate/<name>/structure.yaml`

`Check`, `Prerequisite`, and the trigger types appear inside those declarations
(a gate's `checks`, a file-guard's `require`, a context's `on`). For what each
nature *means*, see the concept pages: [file-guard](/concepts/file-guard),
[gate](/concepts/gate), [context](/concepts/context),
[structure-gate](/concepts/structure-gate).
