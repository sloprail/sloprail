sloprail is not a framework with one big idea. It is a small set of **primitives**
— distinct mechanisms, each doing one thing — that you compose into a guardrail.
Understanding the pieces is understanding the product.

Two of them decide *when a rule runs and what it can do* — the **natures**. The
rest are the **checks** a rule runs to reach a verdict. They combine freely: the
[refactor guide](/use-cases/coding/refactor-regenerated) is a context (a nature)
that runs a reconciliation (a check) and a completeness gate.

## The one rule that shapes everything

Only a **gate** blocks a turn. A **file-guard** refuses a write. A **context**
only tracks — it never blocks. Get that straight and the rest follows.
