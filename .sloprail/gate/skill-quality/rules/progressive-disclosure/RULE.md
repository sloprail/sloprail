# The skill is the entry point; depth lives in linked files

**Mistake:** growing one SKILL.md until everything about the subject is in it —
the common path, the rare path, the full reference, the troubleshooting table,
the worked examples. It is loaded whole, every time, for every task, and a
reader who needs one section pays for all of them.

**Instead:** the skill carries what every reader of it needs — when this applies,
the shape of the work, the decisions and their reasons — and links to a file per
thing only some readers need. Reference tables, long examples, edge-case
procedure and troubleshooting are what move; a one-line pointer stays. Split by
who needs it, not by size: a section every reader must have does not belong in a
linked file merely because the skill got long.

**500 lines is a ceiling, not a target, and this rule does not enforce it.** A
skill at 480 lines is not thereby fine, and the number cannot separate a dense
skill from a padded one — length is a symptom, and enforcing the symptom teaches
splitting a bloated skill into two bloated files, which loads the same bytes and
scores better. What is enforced is the structural question: does a section only
some readers need sit inline instead of behind a link? Cite the line count only
as evidence for that, never as the finding itself. Cutting what nobody acts on
is the neighbouring rule's business, not this one's.
